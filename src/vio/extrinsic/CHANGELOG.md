# 2026-10-18 检出空洞：自动选窗 + 可执行诊断

- 修复"每个 session 都报大空洞"的结构性原因：检测抽样与求解抽样解耦。新增 `detect_rate_hz`（默认 0 = 每帧都检测），`camera_rate_hz` 只在检出通过 PnP 之后抽稀。实测 session11：30.15fps 原流按 15Hz 预抽帧，把 5.36s 的连续可用段切成 4.73s，低于 `min_duration_s` 就被误判成"整段没有可用窗口"。
- 新增 `auto_window`（默认 1）：接受帧按 `max_camera_gap_s` 切段，自动拟合最长且满足 ≥`min_duration_s`/≥`min_frames` 的一段；终端打印选窗与丢弃帧数，`report.json` 新增 `window` 与 `visual_diagnostics`（空洞列表、最长连续段、被拒帧/合格帧清晰度对比）。`--no-auto-window` 保留整段拒绝的老行为。
- `extraction.json` 每帧增加 `accepted`（检出+PnP 达标）、`kept`（真正进入求解）、`sharpness`（拉普拉斯方差）与 `p90`（白格亮度）；`load_dataset` 每 100 帧打印一次进度（原来几分钟没有任何输出）。失败报告也带这些证据，不再是只有一句"大空洞"。
- **把"太暗"和"运动模糊"分开判**：两者都会让检出掉到 0、清晰度下降，但处理方式相反。`visual_diagnostics` 新增 `brightness`（accepted/all p90）与 `too_dark`（判据 p90<45，与 `capture/image_health.py` 一致）；一帧都没通过时退到全体帧亮度再判，所以"全黑数据"也会明确报"太暗"而不是"转太快"。实测 2026-10-18 房间关灯：白格 p90=30/255、584 帧检出 0，旧提示方向是反的。
- 失败路径（包括"有效标定板帧只有 N"这种更早的退出）从 `extraction.json` 重建诊断并打印：空洞几处/各多长、最长连续段多长、是否运动模糊（被拒帧清晰度只有合格帧的 64%），太暗时直接写"先开灯/加补光，不要靠降曝光硬撑"。
- 新增 `calib/windows.py`（纯时间序列）；`--min-duration`、`--detect-rate` 命令行覆盖。
- 修正 `test_aprilgrid_detection_geometry`：`tag_rotation_deg` 默认 180 之后该用例一直失败（自拼板应显式填 0）。新增 tag 旋转对应关系的仿射不变量回归，锁住 2026-10-18 真机 130px PnP 那个坑。
- 回归：40 项单测通过（含暗/亮两个方向的诊断用例）；session11 用默认配置（未改任何门槛）自动选窗到 10.476→15.828s（5.35s、56 帧），残差 1.291px / 0.0079rad/s / 0.0298m/s² 全部通过，与 session09_a、session10_window 的旋转差 1.10°/1.58°、平移差 40/50mm；session12（新采集）自动选窗 4.196→19.460s（15.26s、165 帧）一次通过。证据见 `VALIDATION.md`。
- **IMU 时间戳改用飞控 `time_usec` 的全段下包络锚定**（新 `capture/imu_timebase.py`）。旧方案给每批样本打"本次 read 的宿主时间"、批内用 `time_usec` 反推：批内准，但每批锚点带着读线程积压。2026-10-18 实测 7 次录制、同一台设备同一安装，估出的相机-IMU 时移是 −27.2 / −21.0 / −20.4 / −20.2 / −17.0 / −2.5 / +9.4 ms，而相机侧到包延迟恒定 28.1~28.8 ms（用 v4l2 曝光起点 + `host_receive_monotonic` 量的），且每次录制内部稳定（窗内前半/后半扫描差 ≤2 ms）。标定只能吸收常数时移，吸收不了它逐次变化。新方案录完后用 (宿主收到 − `time_usec`) 的下包络做 Theil-Sen 拟合（含飞控/宿主频率差），所有样本改成"飞控时间 + 该映射"：读线程积压不再进入时间戳，剩下的固定传输延迟仍由标定 offset 吸收。`format_stats` 增加时间基准一行（漂移 ppm、读延迟中位/P95、被回拨量），`imu.csv` 旁写 `imu_timebase.json` 留证；拟合不成立（飞控不发 `time_usec`、时钟非单调/异常、跨度过短）自动回退到读时间并给 warn。
- 新增 `tests/test_imu_timebase.py` 8 项（积压去除、固定延迟保持为常数、漂移估计、无 time_usec/非单调/过短回退、混合样本严格递增、延迟分布）；`capture/selftest_capture.py` 的假飞控改成按墙上时间发 `time_usec`（原来按消息计数，飞控时钟比真实时间快几十万 ppm，会把拟合带偏），并新增时间基准断言，采集自检 59 项全过。**只对以后的录制生效**：已有 `imu.csv` 里的时间戳是按旧方案打的，无法回溯重锚。
