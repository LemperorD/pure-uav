## 2. 报告中不能照搬的结论

### 同 bag 不等于同步；时间单调不等于同一实例

我们实际生成并读取原生 ROS2 Humble bag：bag 记录时间与 header 时间不同仍正确读 header；另在同 bag 中把 IMU header 故意平移 2s，读入后仍保留 2s 差异。bag 只是容器，不会统一驱动的时间域。若驱动已经正确完成共同时间基准映射，确实不需手工锚点；否则不能省略。

严格递增不保证单实例。新增 `header.frame_id` 变化时拒绝，只能发现部分坐标系/实例变化；同名 frame 可掩盖切换。需核查固件、驱动和数据记录。逻辑 IMU 实例与硬件 device_id 也不是同一概念：PX4 gyro/accel device_id 可本来就不同。

### “CUAV 默认 20/10”和“统一减 11ms”没有设备证据

复核报告的二阶 Butterworth 公式是**模拟滤波器直流群延迟**；数字滤波和运动频段应按实际响应计算，不能解释成所有因果滤波都只有一个固定延迟。我们 fs=200Hz 的数字二阶 Butterworth 20/10Hz 反例确实污染了结果，但它是合成设定，不能当成你的 CUAV 实测参数。

核查的 ArduPilot 当前源文件默认值随 vehicle build 变化（所读 Copter/Heli 为20/20，Rover为4/10），并不支持“所有 CUAV 固定20/10”。你可能使用 PX4、其他版本或改过参数；必须核实装机固件和输出链。MAVROS 话题名有 raw 也不能证明飞控未滤波；PX4 部分消息是积分/区间平均量，含两路相对采样时间，不能直接按瞬时同时间样本使用。

相同截止频率未必有相同链路延迟；只打开在线时移估计也不能一般性修复频率相关、两路不一致的滤波响应、漂移或滚动快门。不要据此随意关闭飞控的运行安全滤波。

### 细结点更能拟合运动，但不是普遍更准

高频合成组用 0.12s 时重投影 19.9217px、被拒绝；0.04s 时 0.107918px、平移1.90213mm。**这不是实测手持运动，也不是任何人手运动都会失败的证明**。样条表达能力没有报告声称的严格“约4Hz硬带宽”。

慢运动三组旧种子用新默认均在原门槛内，但其中 seed23 从历史3.96732mm变为4.999454mm，AprilGrid从1.64507mm变为4.73191mm。不能宣称更细默认值普遍提高精度，也不能把 seed23 勉强通过包装成稳定余量；不要改门槛或权重以掩盖它。默认值只是起点，应跨独立窗口检查，并按运动/数据质量对比慢运动配置。

### 其他限定

- 棋盘格本来就支持；AprilGrid不是必选，板尺寸和拓扑必须正确。
- 实测噪声不是“填了会更差”；需要样本标准差/噪声密度、采样和处理链统计定义匹配。权重敏感性只是应做独立评估的理由。
- 不同窗口时移不一致也可由激励不足、模型误差、局部收敛造成；不是滤波/时钟的唯一诊断。
- 板世界系做一致的刚体坐标变换是 gauge，自身不会导致 PnP 失败；错误板尺寸/ID映射也不保证总能响亮失败。
- Gemini RGB 快门类型和读出时长尚未核实。降分辨率/提高帧率不保证消除滚动快门，换采集模式需核对内参。
- Kalibr不能笼统称为“必须Python2”；官方环境已含Python3依赖。本工具不依赖ROS运行时是事实，但并未据此证明Kalibr无法安装。

## 3. 本次实跑结果与局限

27 项单元测试全部通过，包括原生 ROS2 bag、配置类型、话题双层更新、OpenCV YAML 实际解析、采集声明和深度罚项的独立有限差分。七组求解数值见 `VALIDATION.md` 和 `validation/review_20261015/summary.json`。历史13项及原三组数字未篡改。

最重要的负对照：同一组图像，因果 gyro20Hz/accel10Hz 后重投影仅0.083149px，但平移误差13.5877mm、时移误差8.17073ms，求解器仍通过残差检查。**证明当前理想模型仅凭残差无法认证未知滤波数据**。采集声明仅为操作员溯源；未知项会警告，不能冒称自动核实。已知 filtered 声明会拒绝，负对照故意未声明以暴露此边界。

没有真实 Gemini Pro + CUAV 数据，没有装机参数或采集链核查，没有运行该设备 OpenVINS 或给出 ATE。因此此次完成的是软件修订/回归，不是“可以跳过采集链核实直接上机”的认证。

## 4. 实机前最小核查顺序

1. 刚性固定，使用已标定的相机流/分辨率和实测板尺寸。
2. 确认固件版本、IMU逻辑实例、两路滤波/积分/采样时间、驱动轴与单位；获取额外滤波前数据。
3. 验证相机与IMU的共同时间基准，录同bag便于保存但不要把它当同步证据；据实填写采集说明。
4. 用新默认作第一次诊断，看检测图、残差、收敛、参数边界及多个独立窗口；慢运动可对比慢运动profile。不要仅看“passed”。
5. 用正确的相机/IMU话题导出OpenVINS；分别评估 frozen 与 online 时移模式。真实定位精度需要另外的动态VIO序列和独立参考轨迹。
