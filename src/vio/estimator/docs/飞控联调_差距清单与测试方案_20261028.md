## 2. 已确认的缺陷（本轮已修）

### 2.1 P0：ODOMETRY 的 quality 和 reset_counter 传反了

位置：`src/vio/estimator/src/mavlink_link.cpp` 的 `sendVisionPose()`。

MAVLink 生成函数的签名最后三个参数依次是：

```c
mavlink_msg_odometry_pack(..., pose_covariance, velocity_covariance,
                          uint8_t reset_counter,
                          uint8_t estimator_type,
                          int8_t  quality);
```

旧代码按 `(quality, estimator_type, reset_counter)` 传。结果：

| 想发 | 实际发出 |
|---|---|
| quality=90, reset=0 | **reset=90, quality=0** |
| quality=50, reset=2 | **reset=50, quality=2** |

两个现场后果：

1. **飞控看到的 `reset_counter` 随健康状态在 90/50 之间跳。** ArduPilot 在
   `reset_counter` 变化时会把该观测当成"估计器重置"处理（触发位置/速度/姿态重锚定）。
   也就是说：**每切一次 OK↔DEGRADED，飞控就被要求重锚定一次**。
2. **真正的重建次数（1,2,3…）没有发出去。** VIO 重建后位姿会跳变，而飞控不知道，
   会把跳变当成真实运动 —— 这正好是"定位数据发过去了但效果不对"的典型原因之一。

修复：按正确顺序传参，并把"打包"抽成 `MavlinkLink::encodeVisionPose()`，让没有飞控也能做回归。

### 2.2 P0：通信模块的 `pushVisionPose()` 把质量/重置写死

位置：`pure-uav-communication/src/driver/communicate/src/communicator.cpp`。

旧实现固定 `reset_counter=0, quality=0`，协方差固定 `pos_cov[0]=NaN`。即使 VIO 算出了
"质量 90、重建 3 次"，走通信模块也会全部丢掉。

修复：`VisionPose` 增加 4 个带默认值的字段（`quality / reset_counter / pos_sigma_m / vel_sigma_mps`），
`pushVisionPose()` 按字段发送。默认值 = 旧行为，**老调用方不用改一行代码**。

### 2.3 P1：`Communicator::getImu()` 只返回最新一帧

接收线程用覆盖式缓存保存 IMU，VIO 读到的永远是"最近一帧"，中间帧直接丢了。
VIO 的积分需要**每一帧**（漏帧 = 积分少一块，而且时间戳会跳）。

修复：新增逐帧队列 `popImu(TimedImu&)`，每条带：

- `ImuData`（飞控 boot 时间 us + 角速度/加速度）
- `host_ns`（到达主机时的单调时钟，供 `FcuClock` 做主机↔飞控时钟映射）
- 容量可配（默认 2000 ≈ 200 Hz 下 10 秒）、溢出丢最旧帧并单独计数 `droppedImu()`
- 保留 `getImu()`，老模块不受影响

### 2.4 P1：`VisionPose` 缺字段导致"两种定义"

VIO 工作树的 `vision_pose.hpp` 用 `__has_include("communicator.hpp")` 在"集成/独立"两种情况下切换定义。
集成后会用通信模块的结构体，而它原来没有质量/重置字段。本次两边字段已对齐（VIO 侧的
`cam_imu_dt` 是纯诊断字段，用 `PURE_UAV_VISIONPOSE_NO_CAM_IMU_DT` 宏关闭，不参与通信）。

### 2.5 P2：旧补丁 `patches/communicator_imu_callback.patch` 已经失效

它引用 `communicator.cpp` 里的 `data_mutex_`，但现在的通信实现已经改成"每种数据一把锁"，
`git apply --check` 直接失败。**不要再用它**，用 `20261029_02_communicator_integration.patch`。

### 2.6 P1：地面站/其他飞行器的心跳覆盖飞控状态（2026-10-29 修复）

**问题**：两套实现收到任何 `HEARTBEAT` 都直接写 `fcu_sysid_ / autopilot_ / armed_ / connected_`。
同链路如果有路由转发的 QGC/机载计算机/其他飞行器心跳，`armed()` 会被错误改成 `false` ——
已解锁时打开地面零速更新；固件类型和 sysid 也被覆盖。

**修复**：

- 目标飞控身份锁定：显式配置 `fcu_sysid/fcu_compid` 优先；否则自动锁定"第一个像飞控"的心跳
  （`autopilot != INVALID` 且 `type` 不是 `GCS`/`ONBOARD_CONTROLLER`）；
- 锁定后只接受该 `sysid/compid` 的心跳，并只接受该 `sysid` 的 IMU/姿态/位置等数据流；
- 锁定在心跳超时或串口重连时清除，允许飞控重启后重新学习；
- 被忽略的心跳打印前 3 条 + 每 200 条一次，现场能看出"为什么状态没更新"。

**回归**：

- `test_mavlink_link_wire`：飞控解锁心跳 → 地面站心跳(255/GCS/INVALID) ×2 → 其他飞行器(42) →
  飞控自己未解锁心跳。全程 `armed` 只在"飞控自己"发的时候变化，`sysid` 始终是 1；
- `test_vision_pose_wire` §1b：同样场景 + `getAutopilot()` 不被地面站覆盖。

**注意**：链路断开时**不清 armed**（VIO 侧）。空中丢链路若把"已解锁"误判成"地面"，
零速更新会在空中打开；发送本身已被 `connected()` 挡住，保持最后已知状态更安全。

### 2.7 P1：飞控重启后时钟映射不重置（2026-10-29 修复）

**问题**：`HIGHRES_IMU.time_usec` 是飞控 boot 以来的微秒数，重启后从 ~0 重新开始。
旧实现只是继续往 `FcuClock` 里追加样本，重启后的帧会算出"约 303 秒"这种错误时间，
而且 `valid()` 继续返回 true —— IMU、图像、输出位姿落在两个时间基准里。

**修复（两层）**：

1. `FcuClock::addSample()` 改为返回 `AddResult`：
   - 时间戳回退 > 100 ms → `kTimebaseReset`：清空旧样本，本帧作为新基第 1 帧；
   - 轻微回退/重复（< 100 ms）→ `kOutOfOrder`：丢弃，不污染 5% 分位估计；
   - 统计 `outOfOrderCount() / timebaseResetCount()`。
2. `vio_live` 检测到 `kTimebaseReset` 或 `reconnectCount()` 变化时：
   - **暂停发布**（`timebase_recovering`，send 分支同时看 `link.connected()`）；
   - 清空 IMU 队列、相机帧队列、`FcuClock`、图像时间戳平滑（`prev_fed_us/cam_off_us/fed_dt_ms`）、
     IMU 去抖/PLL 状态、`last_sent_ts`；
   - `VioEstimator::resetForNewTimebase()`：换一个全新的 OpenVINS 实例、清锚点/健康/统计窗口、
     `rebuildCount++`（= 给飞控的 `reset_counter`），等新时间基重新初始化后恢复发送。

**为什么不是只调 `clock.reset()`**：估计器内部还停在旧时间基上，下一帧相机时间会从 303 s 掉到 1 s，
OpenVINS 会按 302 秒的间隔做传播，直接发散。

**关于"启动时预热只执行一次"**：启动预热（丢前 150 帧）是为了跳过**程序启动那一刻**
残留的旧时间基块。飞控重启/串口重连后的第一帧本身就是新时间基的起点，再丢 150 帧
既没必要也会延长恢复时间；这里改为"重置 IMU 去抖/PLL 锚定状态，从当前帧重新起网格"。
两种场景分开处理，不是漏了预热。

**回归**：`test_fcu_clock` 模拟"运行约 303 s → 重启到 1.075 s"：

```text
重启后映射: 1.225 s（旧时间基约 303 s）
PASS: FcuClock 时间映射测试通过（含飞控重启/乱序）
```

> 说明：主循环里的"暂停→清队列→重建→恢复"整条链路仍需真机（相机 + 飞控重启/插拔）验收；
> 单测覆盖的是其中可离线验证的部分（检测、映射、估计器重建入口）。

### 2.8 P1：串口拔出/重新枚举后无法恢复（2026-10-29 修复，VIO 链路）

`MavlinkLink` 原来遇到读错误只是 sleep 100 ms，fd 已死就永远收不到数据。飞控重启时
USB CDC 通常会重新枚举，`/dev/ttyACM0` 会短暂消失——不重开串口就再也连不上。

**修复**：检测 `POLLERR/POLLHUP/POLLNVAL` 或读错误 → 关闭 fd、`connected=false`、清 IMU 队列、
停止发送；每 500 ms 用**同一个设备路径**重新 `open()`；成功后 `reconnectCount()++`、
清除身份锁定、等待新心跳。设备路径建议用 udev 固定别名（`/dev/serial/by-id/...`），
否则重新枚举后编号可能改变。

**回归**：`test_mavlink_link_wire` §7 用"软链接 + 换 PTY"模拟重新枚举：
断线 → 自动重连（第 1 次）→ 旧队列为空 → 重新锁定新 sysid=7 → 新数据正常。

> `Communicator` 也已补上同样的重连：`port_.pollIn()` 发现 `POLLERR/POLLHUP/POLLNVAL`
> → 关串口、清队列/锁定/连接态 → 每 500 ms 用 `cfg_.device` 重开 → 重新打招呼并等心跳。
> 回归在 `test_vision_pose_wire` §7（软链接 + 换 PTY，重连后重新锁定 sysid=9）。

## 3. 冻结的接口契约（VIO ↔ 通信 ↔ 飞控）

### 3.1 消息与字段

| 项 | 约定 | 备注 |
|---|---|---|
| 消息 | MAVLink `ODOMETRY`（#331） | 每帧位姿一条 |
| `time_usec` | 飞控 boot 时间（us），来自 `HIGHRES_IMU.time_usec` 同一时钟域 | **不是**主机时间 |
| `frame_id` | `LOCAL_FRD = 20` | 原点 = VIO 初始化时刻机体位置；x = 初始化机头水平投影，y 右，z 下 |
| `child_frame_id` | `BODY_FRD = 12` | 速度是**当前机体系**速度 |
| `x,y,z` | m，`LOCAL_FRD` | z 向下为正 |
| `q` | w,x,y,z；机体系相对 `LOCAL_FRD` | 发送前保证符号连续（q 与 -q 等价） |
| `vx,vy,vz` | m/s，`BODY_FRD` | **比较轨迹时要先转成同一系** |
| `quality` | 0-100；0 = 未知；本次实现 OK=90、DEGRADED=50 | LOST 时不发，不是发低质量 |
| `reset_counter` | 估计器重建次数（clamp 255），单调 | 平时保持常数，**不能随健康状态变** |
| `pose_covariance` | [0]/[6]/[11] = 位置方差（σ²）；[15]/[18]/[20] 姿态 | 未知填 NaN；姿态没估计值就留 0（飞控会 constrain 到配置下限） |
| `velocity_covariance` | [0]/[6]/[11] = 速度方差 | 同上 |
| 发送频率 | ≥ 4 Hz（ArduPilot 文档要求），实际 ~30 Hz（每帧相机一次） | 与相机帧率绑定 |

### 3.2 三条硬规则

1. **一个串口只能有一个程序打开。** 第一次测试用 `vio_live`；正式集成后由 `Communicator` 独占，
   VIO 只调用它的接口。
2. **VIO 的位姿时间戳必须用飞控时钟域。** 在线链路里 `feedImage()` 的时间戳是
   `host_ns → FcuClock → fcu_us` 换算出来的；飞控重启/串口重连时 `FcuClock` 必须 `reset()`，
   否则时间戳会倒退或跳变（本次未改，列在 §7 待测项）。
3. **`LOCAL_FRD` 的 x 不是 NED 的北。** 它是"初始化那一刻机头的水平投影"。接制导/比较轨迹前，
   必须先按初始航向/原点对齐，不能只改坐标系枚举值。

## 4. 两套串口实现怎么收口

| | VIO 的 `MavlinkLink` | 通信的 `Communicator` |
|---|---|---|
| 收 IMU | 逐帧队列（本来就有） | 本次补了逐帧队列 |
| 发位姿 | 本次修好字段顺序 | 本次补了质量/重置/协方差 |
| 收飞控状态 | 心跳/参数/EKF3 速度（诊断用） | 姿态/位置/电池/模式/IMU |
| 适用阶段 | **第一轮效果测试**（少一层依赖） | **正式集成**（唯一串口管理者） |

第一轮不要动通信模块，直接用 `vio_live`；等飞控确认"能收到、能融合"之后，再把 VIO 的
`feedImu()/feedImage()` 接到 `Communicator::popImu()` 上，切换成本很低（接口都是现成的）。

### 5.2 ArduPilot 侧参数清单（若确定是 ArduPilot）

> 依据：ArduPilot 官方 [Non-GPS Position Estimation](https://ardupilot.org/dev/docs/mavlink-nongps-position-estimation.html)
> 与 `AP_VisualOdom_MAV.cpp` 源码（quality 门限、posErr/angErr 的用法）。

| 参数 | 建议值 | 说明 |
|---|---|---|
| `VISO_TYPE` | `1`（MAVLink） | **注意**：官方文档里那段是写给 VOXL 的（写 3）。自己发 ODOMETRY 用 1；3 是 VOXL 专用后端 |
| `VISO_POS_X/Y/Z` | 按实际安装 | 相机/IMU 相对机体原点的偏移（米） |
| `VISO_ORIENT` | 按实际安装 | 0=Forward, 2=Right, 4=Back, 6=Left, 24=Up, 25=Down |
| `VISO_DELAY_MS` | 先 10，再按延迟实测调 | 外部定位相对 IMU 的延迟 |
| `VISO_POS_M_NSE` | 0.2 起（默认 0.2） | 位置噪声下限；协方差更小会被抬到它 |
| `VISO_YAW_M_NSE` | 0.2 起（默认 0.2 rad） | 姿态噪声下限 |
| `VISO_VEL_M_NSE` | 0.1 起（默认 0.1） | 速度噪声下限 |
| `VISO_QUAL_MIN` | **0 → 先测，再改 50** | **默认 0**；`quality < 它` 的帧**不会进 EKF**。当前 VIO 发 90/50，设 50 时 DEGRADED 仍可用；设 90 会把 DEGRADED 全丢掉 |
| `EK3_ENABLE` / `AHRS_EKF_TYPE` | 1 / 3 | 用 EKF3 |
| `EK3_SRC1_POSXY` | 6（ExternalNav） | 水平位置来源 |
| `EK3_SRC1_VELXY` | 6 或 0 | 速度用不用外部 |
| `EK3_SRC1_POSZ` | 6 或 1（Baro） | 高度用外部还是气压 |
| `EK3_SRC1_VELZ` | 6 或 0 | |
| `EK3_SRC1_YAW` | 6 或 1（Compass） | 航向用外部还是罗盘 |
| `LOG_DISARMED` | 1（台架测试时） | 不装桨也能记录 VISP/EKF 日志 |
| EKF 原点 | **必须设置** | 无 GPS 时 EKF 需要一个原点才能起导航；用地面站设，或发 `SET_GPS_GLOBAL_ORIGIN`/`SET_HOME` |

**判读证据在 `VISP` 日志里**：位置/姿态、`posErr`/`angErr`、`reset_counter`、拒绝标志、`quality`
（`AP_VisualOdom_MAV::handle_pose_estimate` 里 `Write_VisualPosition(..., !consume, _quality)`）。
"收到了"看 VISP 条数；"被拒了"看拒绝标志/quality；"融合了"看 EKF 的 innovations 和
`local_position_ned` 是否跟着动。

### 5.3 如果实际是 PX4

需要确认的另一组参数（名称以固件版本为准）：`EKF2_EV_CTRL`（位/速度/航向分别开关）、
`EKF2_EV_DELAY`、`EKF2_EV_POS_X/Y/Z`、`EKF2_EV_QMIN`、`EKF2_EV_NOISE_MD`。
PX4 对 quality/协方差的用法与 ArduPilot 不同，**先确认固件再谈参数**，不要混着抄。

### 11.3 这些工具**不能**证明什么

- 假飞控只解析字段，不做 EKF 融合 → 真正的"飞控采用/融合"仍要看真机 VISP/EKF 日志；
- 合成轨迹不经过相机和 VIO → 它验证的是编码/链路/轴向约定，不是 VIO 精度；
- 离线恢复测试用的是回放时间戳平移，和真实 USB 重新枚举、boot 时间回跳不是一回事，
  真机仍要按 §6 ⑤ 做一次拔插/重启验收。
