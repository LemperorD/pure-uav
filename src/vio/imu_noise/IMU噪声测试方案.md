## 三、已核实的事实（都能复现）

### 3.1 log_2 的加计数据是运动数据，不能用来测噪声

取 I=0 的 132 秒连续段，按 1 秒窗算标准差：

```
段长 132.0 s，267,546 样本，1915.7 Hz 连续

1 秒窗 std 分位:  1% = 0.0089   25% = 0.0225   50% = 0.0352   75% = 0.4032
```

安静窗（0.009 m/s²）和运动窗（0.40 m/s²）混在一起，Allan 拟合 R² 为负。
**结论：这段数据测不出加计噪声密度。**

### 3.2 log_8 的陀螺数据确实是静止的，但含很强的低频漂移

```
2,595,448 样本，1280 秒，各轴整体 std = [0.0313, 0.0130, 0.0143] rad/s
1 秒窗 std: 全部落在 0.00158~0.00164 之间（极其均匀 → 确实是静止录的）
```

但 Allan 偏差随 τ **先升后降**，没有白噪声平台：

| τ | 0.5 ms | 5.7 ms | 59 ms | 0.59 s | 1.9 s | 6 s | 60 s | 190 s |
|---|---|---|---|---|---|---|---|---|
| AD (rad/s) | 1.2e-3 | 7.1e-3 | **2.2e-2** | 8.4e-3 | 8.8e-3 | 6.6e-3 | 2.2e-3 | 9.4e-4 |

### 3.3 报告里的数字复现不出来

`AD(τ=1s)` 用两种独立方法复算（暴力分块 + 库函数）：

```
暴力（1 秒块均值差分/√2）:  AD(1s) = 7.95e-3 rad/s
库 allan_deviation(τ=0.94s): AD     = 8.44e-3 rad/s     ← 两者一致
```

而报告里的 1.57e-3 rad/s/√Hz **隐含** `AD(1s) = 1.57e-3/√fs = 3.5e-5 rad/s`。

**实测 8e-3 vs 隐含 3.5e-5 —— 差 230 倍。** 而且整段数据的 1 秒窗 std 极其均匀，
"换一个安静段"解释不了这个差距。

### 3.4 陀螺白噪声密度的一个自洽估计

在最短 τ（= 1 个采样间隔）处，漂移贡献可忽略，AD 就是纯短期噪声：

```
AD(τ=dt) = 1.226e-3 rad/s      →  σ_d = AD·√(τ·fs) = 1.226e-3 rad/s
相邻样本差分          = 1.734e-3 rad/s  →  σ_d = std(d)/√2 = 1.226e-3 rad/s
```

两条独立路径给出**同一个数** σ_d ≈ 1.23e-3 rad/s。换算成 Kalibr 约定的密度：

```
σ_g = σ_d / √fs = 1.23e-3 / √2026.4 = 2.7e-05 rad/s/√Hz
```

| | 值 | |
|---|---|---|
| 本次从数据算出 | **2.7e-5** rad/s/√Hz | 两条独立路径一致 |
| 工作区在用 | 1.57e-3 | **大 58 倍** |
| IIM42652 数据手册 | 6.1e-5（0.0035 dps/√Hz） | 待查证 |

> ⚠️ 注意：这个 2.7e-5 是**下界**性质 —— 如果飞控在记录前做了低通，
> 真实的传感器噪声会更高。所以正确做法是**测你实际喂给 VIO 的那条流**。

### 3.5 量化是硬限制

```
陀螺 ±2000 dps / 16 bit →  LSB = 1.0653e-3 rad/s = 0.061 °/s
实测相邻样本最小非零差    =  1.0653e-3 rad/s   ← 正好 1 个 LSB
相邻样本完全相同的比例    =  32.5%
```

**相邻样本噪声（约 1.6 LSB）和量化台阶（1 LSB）是同一量级。**
这意味着从这份日志里榨不出高精度的噪声密度。

## 五、两条数据路线

### 路线 A（推荐）：直接录 HIGHRES_IMU，200 Hz，USB

**原理：OpenVINS 吃的就是这条流。**

```
飞控 ──USB CDC──> capture/imu_recorder.py ──> imu.csv (200 Hz)
                                                  │
                                        Allan 方差 ──> 噪声参数
                                                  │
                                        OpenVINS 的 /imu0 就是它
```

| 项 | 说明 |
|---|---|
| 需要新硬件吗 | **不要**。不用 SD 卡、不用读卡器、不用管日志下载 |
| 采样率 | 200 Hz（USB CDC 是 12 Mbps，带宽绰绰有余） |
| 测的是谁 | **正是 VIO 实际收到的那条流**（含飞控滤波、降采样、传输） |
| 测不到 | 传感器 2 kHz 原始噪声（但那不是 VIO 吃的） |
| 时长 | 噪声密度 ~10 分钟够；随机游走要 **4~8 小时** |
| 文件大小 | 200 Hz × 8 h ≈ 580 万行 ≈ 400 MB CSV |

### 路线 B：DataFlash 原始数据 + 批采样，2 kHz

| 项 | 说明 |
|---|---|
| 需要新硬件吗 | **要 SD 读卡器**（MAVLink 下载之前反复失败） |
| 要改的参数 | `INS_LOG_BAT_MASK`、`INS_LOG_BAT_OPT` |
| 优点 | 2 kHz、可选滤波前/后，能看传感器真实噪声 |
| 缺点 | 麻烦；而且**测的不是 VIO 吃的那条流** |

> ⚠️ `INS_LOG_BAT_OPT` 的位定义**没有从官方文档确认**（外网被挡）。
> 之前的笔记写的是"4 = 滤波前后采样"，这**未经验证**。
> log_1 里有 1301 条 ISBD 可以反推，但要单独验。

### 推荐组合

**先做 A**（省事、且直接对得上 VIO），有时间再做 B 交叉验证。

## 六、路线 A 的具体步骤

### 第 1 步：物理条件（关键）

```
□ 飞控平放在桌上，USB 供电，不接电机、不装桨
□ 桌面稳固，人别碰桌子；附近不要有风扇/空调直吹
□ 室温稳定（MEMS 零偏随温度漂）
□ 笔记本接着电源，别休眠
```

### 第 2 步：录 8 小时

用 `capture/imu_recorder.py`（已有）或新的录制脚本，输出到一个专门的静态文件。

- 前 30 秒先别动，用来确认数据正常
- 中途不要碰飞控
- 录完检查：样本数 ≈ 200 × 秒数；无大空洞；时间戳严格递增

### 第 3 步：分析（工具待建，必须满足这些判据）

```
□ 先在【合成数据】上验证：给定 σ 和 K，能不能反解回来（误差 < 15%）
□ 噪声密度：在【-1/2 斜率区】拟合，外推读 τ=1s
□ 随机游走：在【+1/2 斜率区】（长 τ 端）拟合
□ 必须打印：【用了哪段 τ】【拟合 R²】【三轴一致性】
□ 曲线形状不对就【拒绝出数】，不许硬给一个值
□ 出图：Allan 偏差双对数图 + 拟合线
```

### 第 4 步：回填 + 验证

```
1) 写进 ~/vio_ws/final_config/kalibr_imu_chain.yaml
2) 写进 ~/calib/ov_config_session05/kalibr_imu_chain.yaml
3) 重跑 session05 的 OpenVINS
4) 对比：新参数 vs 旧参数的轨迹和残差
```

**第 4 步才是唯一能验证的数字对不对的方法。**
